## 1. The Process Model

The Python engine already exists and is not being rewritten. That single fact
decides the architecture before any shell is chosen:

```
┌───────────────────── Tauri v2 shell (Rust) ────────────────────────────┐
│  owns: window · native dialogs · sidecar lifecycle · tray · updater    │
│                                                                        │
│  ┌────────────────── webview: Vue 3 (Vite) SPA ──────────────────────┐ │
│  │   crawl config  ·  pipeline  ·  gallery  ·  character detail      │ │
│  │            fetch + EventSource → 127.0.0.1:<ephemeral>            │ │
│  └───────────────────────────────────────────────────────────────────┘ │
│         ▲ invoke("daemon_endpoint") → {port, token}                    │
└─────────┼──────────────────────────────────────────────────────────────┘
          │ spawn + stdout handshake + kill on exit
┌─────────▼──────────────────────────────────────────────────────────────┐
│  dawnmaker  (Python, FastAPI + uvicorn, bundled via PyInstaller)      │
│    api/       REST + SSE            jobs/   queue, worker, cancel      │
│    thumbs/    WebP on ingest        reaver/ ← existing engine       │
└─────────┬──────────────────────────────────────────────────────────────┘
          │
    ┌─────┴───────────────────┐
    ▼                         ▼
~/.reaver/reaver.db   <library folder>/ blobs/ thumbs/ by-character/
```

**The webview never touches the filesystem.** Images reach the grid over
`http://127.0.0.1:PORT/api/media/{sha}/thumb`, not `file://` and not `asset:`.

That is a deliberate choice against the Tauri-native option. `convertFileSrc` +
the asset protocol would mean Rust needs to know the library path, the fs scope
must be widened to a user-chosen directory and persisted, and the thumbnail
pipeline — which is Python — would be serving through a channel Python doesn't
own. Going over loopback keeps one code path, keeps authorization in one place,
and means the day you want to browse the archive from your phone on the LAN it
already works.

### Binding to localhost safely

A localhost port is reachable by any process on the machine, including a
browser tab on a malicious page (DNS rebinding). Three cheap defences:

1. Bind `127.0.0.1` on an **ephemeral port** (`port=0`).
2. A **per-launch bearer token**, generated by the daemon at startup and handed
   to Rust over the stdout pipe — never written to a file, which any process
   could read.
3. Reject requests whose `Host` is not `127.0.0.1:<port>` or whose `Origin` is
   not the app's own. This is what actually kills DNS rebinding.

## 2. Shell: Tauri v2 + Python sidecar

Decided. The costs are real and each has a specific answer — this section is
those answers, because they are the part that bites during packaging week.

Worth knowing going in: the "Tauri is 96% smaller" benchmark does not apply
here, because this app ships a Python runtime either way. A PyInstaller build of
the engine (httpx, Pillow, uvicorn, gallery-dl) is ~55–70 MB, so the bundle
lands around 70 MB rather than 10. The reasons to pick Tauri are the tray icon,
the updater, native dialogs, and not shipping a Chromium — not the size chart.

### 2.1 Sidecar lifecycle — three layers, because one is not enough

This is the failure mode that defines the app: **a crawl holds a rate-limit
budget and a live network session.** An orphaned `dawnmaker` keeps hitting
pixiv with nobody watching, and a second one started by the next launch fights
the first over the same SQLite file.

**Layer 1 — Rust owns the child.** Spawn in `setup()`, keep the `CommandChild`
in `app.manage()`, and kill it on `RunEvent::ExitRequested` *and* on the main
window's `WindowEvent::Destroyed`. Covers the ordinary quit.

**Layer 2 — heartbeat, in the daemon.** The frontend `POST /api/heartbeat`
every 5 s; the daemon exits if it hasn't heard one in 30 s. This is the layer
that covers what Layer 1 cannot: `kill -9` on the shell, a Rust panic, a
force-quit. Parent-PID polling is the usual suggestion and is worse — `getppid()`
is meaningless on Windows and reparenting is not reliably observable on macOS.

One wrinkle worth handling on day one: **laptop sleep suspends both processes.**
Compare heartbeat gaps on a monotonic clock, and if the gap exceeds ~5 minutes,
treat it as a wake rather than a death and grant one grace period. Otherwise
every lid-close kills a running crawl.

**Layer 3 — a lockfile.** `~/.reaver/dawnmaker.lock` holding `{pid, port,
started_at}`. On startup, if a live process holds it, attach to that daemon
instead of starting a second one. Two daemons on one SQLite file is how the
archive gets corrupted, and it is entirely preventable here.

### 2.2 Port and token handshake

The sidecar binds port 0 and prints exactly one line on stdout before serving:

```
DAWNMAKER_READY {"port":51234,"token":"9f2c…","pid":8123}
```

Rust reads `CommandEvent::Stdout`, parses that line, stores it in managed state,
and exposes it to the webview through a Tauri command:

```rust
#[tauri::command]
fn daemon_endpoint(state: State<Endpoint>) -> Endpoint { state.inner().clone() }
```

The frontend calls it once at boot and holds the values in a Pinia store. The
stdout pipe is private to the parent process — that is the whole reason the
token travels this way rather than through a file or an argv (argv is visible in
`ps` to every user on the box).

### 2.3 CSP — the config that will silently break the gallery

Tauri's CSP is **off unless you set it**, and the moment you set it, a
`fetch()` and an `<img src>` to loopback are blocked with no useful error. The
port is ephemeral, so the policy needs a port wildcard, which CSP host-sources
do allow:

```json
"app": {
  "security": {
    "csp": {
      "default-src": "'self'",
      "connect-src": "'self' ipc: http://ipc.localhost http://127.0.0.1:*",
      "img-src":     "'self' data: blob: http://127.0.0.1:*",
      "style-src":   "'self' 'unsafe-inline'"
    }
  }
}
```

The loopback restriction is what carries the security here; wildcarding the port
costs nothing real.

### 2.4 Packaging: use `bundle.resources`, not `externalBin`

`externalBin` copies **one file** per target triple, named
`dawnmaker-x86_64-pc-windows-msvc.exe` and so on. PyInstaller's `--onedir`
output is a directory, so it does not fit. The two routes:

| | `--onefile` + `externalBin` | **`--onedir` + `bundle.resources`** |
|---|---|---|
| Cold start | 1–3 s — extracts the whole runtime to temp **every launch** | instant |
| Windows AV | the extract-and-exec pattern is what heuristics flag | normal file layout |
| Spawning | `shell:allow-execute` capability, `Command::sidecar()` | `std::process::Command` on a resolved resource path |
| Updater | known issue: NSIS installer does not replace `externalBin` on update | replaced like any resource |

Take the second. `bundle.resources` accepts a directory (`"sidecar/":
"sidecar/"`), and you resolve it at runtime:

```rust
let exe = app.path()
    .resolve("sidecar/dawnmaker", BaseDirectory::Resource)?;
```

You give up Tauri's sidecar helper, but you were writing the lifecycle
management by hand anyway (§2.1), so the helper was buying very little.

### 2.5 Signing and notarization — two binaries, one order

macOS notarization requires **every Mach-O in the bundle** to be signed with the
hardened runtime — that means the `dawnmaker` executable *and* every `.so` and
`.dylib` PyInstaller drags in. `codesign --deep` is unreliable for this; sign
leaves first, then let Tauri sign the app bundle:

```
find sidecar -name '*.so' -o -name '*.dylib' -o -type f -perm +111 \
  | xargs -I{} codesign --force --timestamp --options runtime -s "$DEV_ID" {}
# then: tauri build   (signs and notarizes the .app around it)
```

Add entitlements only if notarization or launch actually fails — start with
none, and reach for `com.apple.security.cs.allow-jit` only if a dependency
demands it. On Windows, sign the sidecar `.exe` as well or Defender will
quarantine it out of the install directory.

### 2.6 macOS folder access — Tauri's fs scope does not cover the sidecar

Worth being explicit, because it is a common wrong assumption: `tauri-plugin-fs`
scope constrains **the webview and Rust**. The sidecar is an ordinary child
process running with the user's permissions; nothing in Tauri sandboxes it.

What *does* apply is TCC: the sidecar inherits the parent app's identity, so
touching `~/Documents`, `~/Desktop` or `~/Downloads` raises a system prompt
attributed to your app — and if it is denied, Python gets a bare `PermissionError`
with no way to re-prompt itself. Two practical consequences:

- Default the library folder somewhere outside those three (`~/CurioLibrary`,
  or an external drive). Sidesteps the prompt entirely.
- Folder selection goes through `@tauri-apps/plugin-dialog` (the native picker,
  which grants access as a side effect), and the chosen path is handed to the
  daemon via `PUT /api/config`. On `PermissionError` the daemon returns a
  distinct error code and the UI re-opens the picker rather than showing a stack
  trace.

### 2.7 Dev loop — do not rebuild PyInstaller to change a Python file

`beforeDevCommand` runs Vite. For the sidecar, branch on `cfg!(debug_assertions)`
and spawn `python -m dawnmaker` from the venv (overridable with
`REAVER_DEV_CMD`) instead of the bundled binary. The handshake line is
identical either way, so nothing else in the app knows the difference — and the
Python edit-restart cycle stays at zero seconds.

### 2.8 Note on Nuxt

Use **Vue 3 + Vite**, not Nuxt. Nuxt's value is SSR, server routes and SEO;
inside a webview none of those apply, and you would spend the setup disabling
Nitro (`ssr: false`, static generate) and debugging it. `vue-router` +
`unplugin-vue-router` gives you the file-based routing, which is the only part
worth missing. If you want Nuxt anyway for familiarity, run it `ssr: false` +
`nuxt generate` and treat the output as a static SPA.

## 3. Storage — the library folder

The user picks one folder. Everything derived lives under it, so the archive is
one portable directory:

```
<library folder>/
├── blobs/       69/9a/699ab3bb…f6.png     content-addressed, the write path
├── thumbs/      69/9a/699ab3bb…f6.webp    400px WebP, generated on ingest
└── by-character/
    └── ganyu/   artist_1234567_p0.png     ← hardlink to the same inode
```

`~/.reaver/reaver.db` stays in the app-data dir, **not** in the library folder.
SQLite over a synced or network folder is how databases get corrupted. The db
holds a `library_root` and every blob is addressed by hash, so moving the folder
is one settings change and zero migrations.

### 3.1 Content-addressed *and* human-browsable — hardlinks, not symlinks

The tension is real: content addressing is what makes dedupe, atomic writes and
db/disk consistency work, and it is also completely unreadable in Finder. The
usual resolution is a symlink tree, and it is a bad one — symlinks break when
copied, do not survive a zip round-trip, and on Windows need either developer
mode or an elevation prompt.

**Hardlink instead.** `blobs/69/9a/<sha>.png` and
`by-character/ganyu/artist_123456_p0.png` are two names for one inode: zero
extra bytes, and each name is a *real file* to every other program on the
machine. The library becomes a normal folder you can browse, drag into Krita,
or point a wallpaper rotator at, with the app closed.

`os.link()` covers macOS, Linux and NTFS. The constraint is that both names must
be on the same filesystem — satisfied by construction here, since both trees are
inside the one library folder.

Three consequences to handle rather than discover:

- **Detect the capability at library-init.** Create a temp file, `os.link()` it,
  and record `link_mode` = `hard | symlink | copy` in the db. exFAT and FAT32
  external drives — a plausible place to keep an art archive — have no
  hardlinks, and the fallback must be a decision, not an exception trace.
- **Deleting from `by-character/` frees nothing** while the blob holds the other
  link. `POST /library/gc` drops blobs whose only remaining link is the blob
  itself and which no `media` row references.
- **Do not put the library in Dropbox / iCloud / OneDrive.** Sync clients
  generally materialise each hardlink as an independent copy, silently doubling
  the archive, and some break the link outright. Warn at folder-pick time if the
  chosen path is under a known sync root.

`by-character/` remains *derived* — `POST /library/reindex` rebuilds it from the
db, and deleting the whole tree loses nothing. That is what makes it safe for
the user to reorganise it however they like.

### 3.2 Adopting a folder you already have

"Point the app at my existing art folder" is a different product — an organiser,
not a watcher — because **the metadata is not recoverable from a bare JPEG**.
Artist, post id, tags and posted date do not survive a download; filename
heuristics recover a fraction at best.

So it is an *import*, not a storage mode, and one storage model survives:

```
coreflame import <dir> [--move]
```

For each file: hash → skip if the sha is already stored → dHash → if it matches
a known post within threshold, adopt it under that post (this is how a folder of
previously hand-saved pixiv downloads gets its metadata back) → otherwise store
it as `unsourced`, with the original filename kept as a hint for later matching.

`unsourced` items appear in the gallery under an "Unsorted" pseudo-character, so
they are visible rather than silently swallowed. Default is copy; `--move` is
opt-in, because an import that eats the originals on a first run is not
recoverable.

### 3.3 Thumbnails are not optional

A grid of 500 cards pointing at 8 MB PNGs will move ~4 GB through the webview
and stall it. Generating a 400px WebP at ingest costs ~30 ms per image once, and
turns a grid page into ~15 KB per card. This is the single highest-impact
decision in the gallery.

## 4. Job model

One job queue, **one worker thread**. Not a pool — the constraint is the remote
rate limit, not local CPU, and two workers hitting pixiv concurrently just
doubles the ban risk while halving the per-worker budget. Media downloads within
a job may use a small bounded pool (default 3) because they hit a different host
with its own budget.

```
job = { id, type, params, state, progress, counters, started_at, finished_at, error }

type   : poll | link | media | backfill | reindex
state  : queued → running → (succeeded | failed | cancelled)
```

Jobs are persisted. A job `running` at startup with no live thread is marked
`interrupted` on boot rather than silently forgotten — that row is how you find
out a crawl died at 3am. Cancellation is cooperative: the worker checks a flag
between records, so a cancel lands within one HTTP request, never mid-write.

**Progress is derived, not guessed.** For a pixiv poll the denominator is
`illustManga.total` from the first search page; for media it is the count of
`state='pending'` rows at job start. When there is no honest denominator the API
sends `total: null` and the UI shows an indeterminate bar rather than a lying
percentage.

## 4b. Visited marking, tag observation, and the config feedback loop

Three specs that turn out to be one feature: **the crawl teaches the config.**

### 4b.1 The visited set — mark before you spend a request

A character's artworks are reachable from several directions at once, and the
current watermark does not cover it. `poll_pixiv` keeps a watermark per
`tag:<tag>`, so artwork `128994201` tagged both `甘雨` and `甘雨(原神)` is
below neither watermark on the second tag and gets a **full detail request
again** — once per tag, per character that shares it. Two tags per character is
2× the detail traffic; the shared-universe tags are worse.

The fix is cheap because the search listing already hands over `illustId`
*before* any detail request is spent. So the gate goes there:

```
for item in search_page:                 # illustId is free here
    if seen(source, illust_id):          # one indexed SELECT
        continue                         # <- the request that never happens
    rec = detail(illust_id)              # 1-2 requests
```

`posts` cannot be that gate, because it only holds artworks we **kept**. The
visited set has to be the superset — everything ever observed, including what
was rejected and what no longer exists:

```sql
CREATE TABLE seen_posts (
    source        TEXT NOT NULL,
    external_id   TEXT NOT NULL,
    state         TEXT NOT NULL,   -- indexed | skipped | gone | failed
    reason        TEXT,            -- below_min_bookmarks | r18_excluded |
                                   -- ugoira | http_404 | http_410
    threshold     INTEGER,         -- the config value that caused a skip
    first_seen    TEXT NOT NULL,
    last_seen     TEXT NOT NULL,
    retry_after   TEXT,            -- transient failures only
    PRIMARY KEY (source, external_id)
);
CREATE INDEX seen_state ON seen_posts(state, retry_after);
```

**The four states are four different retry policies, and collapsing them is the
bug.**

| State | Meaning | Revisit? |
|---|---|---|
| `indexed` | kept; a `posts` row exists | Never. Metadata refresh is a separate, explicit job |
| `skipped` | deliberately rejected — under `min_bookmarks`, R-18 excluded, ugoira | **Only if the config that rejected it changes** |
| `gone` | 404/410 — deleted or made private | Never |
| `failed` | 5xx, timeout, connection reset | After `retry_after`, with backoff |

Two consequences worth being deliberate about:

- **`gone` must be recorded, or the crawl re-fetches deleted artworks forever.**
  It also has to propagate: an existing `posts` row for a now-`gone` id is
  marked so the gallery greys it and `library gc` can release the blob — which
  is what the ToS section asks for anyway ("deleted or privated works should be
  removed from your archive too").
- **`skipped` stores the threshold that caused it.** Without that, lowering
  `min_bookmarks` from 500 to 100 silently does nothing: every newly-eligible
  artwork is already in the visited set. The invalidation rule is one query —
  `DELETE FROM seen_posts WHERE state='skipped' AND reason='below_min_bookmarks'
  AND threshold > :new_value` — run when the watch is saved, and the config form
  says how many artworks it re-opened.

The same gate serves X: `gallery-dl`'s output is filtered against `seen_posts`
before any media URL is fetched.

### 4b.2 Observed tags — what a character is actually tagged with

Every artwork that passes the gate contributes its tag list. Aggregated per
character, that is a map of how the fandom actually labels this character —
which is exactly the input the config screen is missing.

```sql
CREATE TABLE post_tags (
    source TEXT, external_id TEXT, tag TEXT,
    PRIMARY KEY (source, external_id, tag)
);
CREATE INDEX post_tags_tag ON post_tags(tag);

CREATE TABLE tag_stats (             -- derived; rebuildable from post_tags
    slug        TEXT NOT NULL,
    tag         TEXT NOT NULL,
    translated  TEXT,
    posts       INTEGER NOT NULL,    -- posts for this character carrying it
    share       REAL NOT NULL,       -- posts / posts_for_character
    score       REAL NOT NULL,       -- see below
    state       TEXT NOT NULL,       -- watched | suggested | ignored
    PRIMARY KEY (slug, tag)
);
```

**Ranking by frequency is wrong, and obviously so once you look at the data.**
`原神` (Genshin Impact) appears on ~100% of Ganyu artworks — top of any
frequency list, and useless as a character tag: watching it means crawling the
entire game's fanart. The tag worth suggesting is the one that is *frequent for
this character and rare for every other one*:

```
score = share_in_character × log(total_characters / characters_carrying_tag)
```

That is TF-IDF's shape, and it does the right thing here: `甘雨(原神)` has
near-1 share and appears for one character → high; `原神` has share 1.0 across
every watched character → log(1) = 0 → suppressed automatically, with no
hand-maintained stopword list. Costume and event variants (`甘雨(飛花逐月)`)
land in between, which is where they belong — worth offering, not worth
auto-adding.

### 4b.3 The loop closes on the config screens

Observation is only worth collecting if it can be acted on in one click, so both
config surfaces write back:

- **Character detail** — an *Observed tags* strip under the header: the ranked
  tags with their share, each offering **Watch** (append to
  `watches.pixiv_tags`, queue a backfill for that tag alone) or **Ignore**
  (`state='ignored'`, never suggested again). This is where you discover that
  40% of the character's art carries a tag you were not crawling.
- **Add/edit character form** — a *Suggested tags* rail on the right, same
  ranking. For an existing character it reads `tag_stats`. **For a brand-new
  character there is no history — and it still works**, because the pixiv search
  listing returns `tags[]` on every item: rank the co-occurring tags from page 1
  of the preview search already being fetched for validation. No extra request,
  and suggestions appear before the first crawl.

```
GET  /gallery/{slug}/tags?state=&limit=40   → ranked observed tags
POST /watches/{slug}/tags                   ← {tag, action: "watch"|"ignore"}
GET  /watches/suggest?pixiv_tag=甘雨         → ranked co-occurrence from the
                                              preview search (new characters)
GET  /stats/seen                            → {indexed, skipped, gone, failed}
```

### 4b.4 Failure modes

| Symptom | Root cause | Guard |
|---|---|---|
| Detail traffic scales with tag count, not artwork count | No pre-detail gate | Check `seen_posts` from the search listing (§4b.1) |
| A deleted artwork is re-fetched every poll forever | 404 recorded nowhere | `state='gone'`, never retried |
| Lowering `min_bookmarks` changes nothing | Skips are permanent | Store `threshold`; invalidate on config save |
| One flaky 500 blacklists an artwork permanently | `failed` treated as `gone` | Separate states, `retry_after` + backoff |
| Suggestions are all series/franchise tags | Ranked by frequency | Rarity-weighted score (§4b.2) |
| `seen_posts` grows without bound | Every observed id is kept | It is meant to — one row is ~60 bytes; a million artworks is ~60 MB and saves millions of requests |

## 4c. Network path — working through DNS interference

Not future-proofing: **pixiv is among the sites Indonesian ISPs interfere with**,
so on the developer's own connection this is a day-one blocker, not a later
nice-to-have. It belongs in the fetch layer from the start, because retrofitting
a resolver under a working HTTP stack is far more disruptive than designing the
seam in now.

### 4c.1 Know which layer is actually blocking you

Indonesian ISPs do not use one technique. Reported behaviour, fixed and mobile:
**DNS hijacking and redirection, SNI filtering, TCP resets, and DPI** — and
fixed ISPs increasingly **block the alternative resolvers themselves**. Mobile
operators are the harder case; several already block third-party DNS outright.

That matters because the fixes are not interchangeable:

| Interference | Symptom | What fixes it |
|---|---|---|
| DNS hijack / redirect | Hostname resolves to a block-page IP or `0.0.0.0` | **DoH** — encrypted resolution the ISP cannot answer for you |
| SNI filtering / DPI | Correct IP resolves, TCP connects, then the handshake is reset | **Nothing DNS-level.** Needs a proxy/tunnel (or ECH, which needs server support) |
| IP blackhole | Connection times out to the real IP | Proxy/tunnel |
| TLS interception | Certificate does not validate | **Stop. See §4c.4** |

So the design is two independent layers with a diagnostic that says which one
you need — not a single "bypass" switch.

### 4c.2 Layer 1 — resolve through DoH inside `SourceClient`

The seam is the connection step, not the request. Subclass httpcore's network
backend so `connect_tcp` resolves the hostname over DoH and dials the returned
IP, while still passing the **original hostname** as `server_hostname` for SNI
and certificate validation:

```python
class DohBackend(httpcore.SyncBackend):
    def connect_tcp(self, host, port, timeout=None, local_address=None,
                    socket_options=None):
        ip = self.resolver.resolve(host)          # cached, honours TTL
        stream = super().connect_tcp(ip, port, timeout, local_address,
                                     socket_options)
        return stream            # TLS upgrade still uses `host` for SNI + verify
```

Roughly 60 lines including a TTL cache. Config is per-install, not per-source:
`resolver: system | doh`, `doh_endpoint` (Cloudflare, Google, Quad9 — make it a
list and fail over), and a negative-result rule: **a DoH answer of `0.0.0.0` or
an RFC1918 address is interference, not an answer** — reject it rather than
dialling it.

### 4c.3 Layer 2 — a proxy, because it is the only thing that covers both sources

Two reasons this cannot be skipped:

1. **DoH does not survive SNI filtering.** When the block is DPI-based, the
   resolver was never the problem.
2. **`gallery-dl` has its own network stack** (requests) and cannot be handed
   our resolver. A proxy is the *only* setting that covers the pixiv path and
   the X path with one configuration — `httpx(proxy=…)` on our side,
   `--proxy` / `HTTPS_PROXY` on gallery-dl's.

So: one optional `proxy_url` in config, applied to both adapters, off by
default. The app does not ship or embed a proxy — the user points it at
whatever they already run.

### 4c.4 Never disable certificate verification

The reflex when a blocked site throws TLS errors is `verify=False`, and here it
is exactly backwards. At least one Indonesian ISP has been observed attempting
**HTTPS interception with a spoofed certificate**. A validation failure is
therefore *evidence of an active MITM*, and turning verification off converts a
failed interception into a successful one — handing over the `PHPSESSID` and the
X `auth_token` in the process.

`verify=False` must not exist as a config option, a debug flag, or a fallback.
On a validation failure the daemon surfaces "the connection is being
intercepted" and stops. This is the one place in the design where the honest
behaviour is to refuse to continue.

### 4c.5 The diagnostic tells you which layer

`POST /net/diagnose` runs four steps against a target host and reports where it
breaks — this is what turns "pixiv doesn't work" into an actionable answer:

```
1. system DNS      → pixiv.net = 104.18.x.x   |  = 0.0.0.0 / block page  → hijack
2. DoH             → pixiv.net = 104.18.x.x   |  resolver unreachable    → resolver blocked
3. TCP connect     → open                     |  timeout                 → IP blackhole
4. TLS handshake   → cert valid, SNI ok       |  reset      → SNI/DPI
                                              |  bad cert   → INTERCEPTION, stop
```

Step 1 vs step 2 disagreeing is the clean signature of DNS hijacking, and it is
the only way to know DoH will be enough before turning it on.

### 4c.6 Where it appears in the UI

The crawl-configuration status row gets a **Network** card alongside pixiv, X,
library and the visited index: resolver mode, whether DoH is reachable, proxy
on/off, and a **Diagnose** action that runs §4c.5 and names the layer. A crawl
that dies on connection errors should point at that card rather than filling the
log with tracebacks.

### 4c.7 Failure modes

| Symptom | Root cause | Guard |
|---|---|---|
| Every pixiv request fails on a specific ISP | DNS hijack | DoH resolver (§4c.2) |
| DoH configured, still blocked | SNI filtering / DPI — DNS was never it | Proxy layer (§4c.3); the diagnostic says which |
| Works on wifi, fails on mobile data | Mobile operators block third-party resolvers | Fail over across DoH endpoints, then proxy |
| Session cookie leaked | `verify=False` used to get past TLS errors | The option does not exist (§4c.4) |
| pixiv works, X does not | gallery-dl cannot use our resolver | Proxy is the shared setting (§4c.3) |
| Resolver returns a block-page IP and we dial it | Treating any answer as valid | Reject `0.0.0.0`/RFC1918 answers (§4c.2) |
| Certificate errors "fixed" by retrying | Interception mistaken for flakiness | Refuse and surface it; never retry past a cert failure |

## 5. The four pages and what each needs

### 5.1 Crawl configuration — *controls and dispatches*

- Table of watches: slug, label, pixiv tags, X match terms, min bookmarks, R-18,
  last poll, post count.
- Tag editor with **live validation**: `POST /api/watches/validate` hits pixiv
  once and returns the result count, so a typo'd tag is caught at 0 results
  instead of after a silent empty crawl. This is worth the round-trip.
- Credential status from `/api/sources/status` — the `doctor` output, surfaced:
  PHPSESSID present, gallery-dl found, X cookies present/expiring.
- Folder picker → `PUT /api/config {library_root}`.
- Dispatch: run-now buttons per job type, optional per-watch. Posts to
  `/api/jobs` and routes to the pipeline page.
- Schedule: a cron expression per job type, evaluated by the daemon.

### 5.2 Worker pipeline — *live*

Subscribes to `GET /api/events` (SSE). Shows the queue, the running job's stage
(`discover → detail → link → download`), per-source counters, a rolling log, and
the rate-limit budget remaining. Cancel button per job.

SSE over WebSocket deliberately: this stream is one-directional, EventSource
reconnects on its own, and cancellation is a normal POST. A WebSocket here buys
nothing and costs reconnection logic.

### 5.3 Gallery — characters

Grid of character cards, each with the **thumbnail of the most recently posted
image** for that watch, plus counts. One query, no N+1:

```sql
SELECT w.slug, w.label, cover.sha256, cover.posted_at, cnt.n
FROM watches w
LEFT JOIN (
  SELECT pw.slug, m.sha256, p.posted_at,
         ROW_NUMBER() OVER (PARTITION BY pw.slug
                            ORDER BY p.posted_at DESC, p.external_id DESC) rn
  FROM post_watches pw
  JOIN posts p  ON p.source=pw.source AND p.external_id=pw.external_id
  JOIN media m  ON m.source=p.source AND m.external_id=p.external_id
  WHERE m.state='stored'
) cover ON cover.slug=w.slug AND cover.rn=1
LEFT JOIN (SELECT slug, count(*) n FROM post_watches GROUP BY slug) cnt
  ON cnt.slug=w.slug;
```

### 5.4 Character detail — grid + slide-over aside

An **Observed tags** strip sits under the header (§4b.3): the ranked tags this
character's artworks actually carry, each with its share and a one-click
Watch / Ignore. It is the highest-value thing on the screen after the images
themselves, because it is where the config gets corrected.

Virtualized grid of that character's images. **Keyset pagination, not offset** —
`?cursor=<posted_at>|<external_id>&limit=100`. Offset pagination silently
duplicates and skips rows when a crawl inserts newer posts while the user is
scrolling, which on this app happens constantly.

Clicking a tile opens an aside sliding from the right (`transform: translateX`,
`transition` 200ms, `prefers-reduced-motion` respected) showing: full image,
title, artist + link, source badge, posted date, tags, dimensions, file size,
sha256, **the other source's copy if dedupe linked one**, and an "open source
post" button. The grid stays mounted underneath — the aside is a detail panel,
not a route change, so browser-back closes it via a history entry.

The cross-source link is the payoff of the phash work and should be visible:
"also posted on X · 2026-08-21" with a link.

## 6. API contract

Base `http://127.0.0.1:{port}/api`. All requests carry
`Authorization: Bearer {token}`. Errors are
`{"error": {"code": "...", "message": "...", "detail": {...}}}`.

### Config & status

```
GET    /health                       → {ok, version, library_root, db_path}
POST   /heartbeat                    ← {}  every 5s from the shell; no beat for
                                        30s (monotonic, sleep-aware) → daemon exits
GET    /config                       → Config (secrets redacted to booleans)
PUT    /config                       ← {library_root?, pixiv_rate?, dupe_threshold?,
                                        twitter_cookies_file?, twitter_timeline_limit?}
GET    /sources/status               → {pixiv:{authed,user_id,ok,checked_at},
                                        twitter:{gallery_dl:{found,version},
                                                 cookies:{present,expires_at}}}
POST   /sources/pixiv/session        ← {php_sessid}         (design; superseded by /auth/pixiv)
GET    /stats                        → engine stats + library bytes on disk
POST   /auth/pixiv                   ← {php_sessid}  verified with one search BEFORE
                                        it is stored (secrets.json 0600)
                                        → sources status · 400 bad_cookie · 401 session_rejected
POST   /auth/pixiv/verify            → sources status (re-runs the one-search check)
DELETE /auth/pixiv                   → 204 (forgets the session)
POST   /auth/twitter                 ← {auth_token, ct0} → sources status; written as
                                        ~/.reaver/twitter-cookies.txt for gallery-dl, unverified
DELETE /auth/twitter                 → 204
POST   /net/diagnose?host=           → {host, verdict, advice, steps, system_ip, doh_ip}  (§4c.5)
```

`GET /sources/status` as built returns
`{pixiv:{authed,user_id,verified,checked_at,error}, twitter:{authed,gallery_dl,cookies_file,from_browser}, network:{resolver,proxy}}`
— `verified` is `null` until the background check lands, `false` = expired.

### Watches

```
GET    /watches                      → [{slug,label,pixiv_tags,match_terms,
                                         min_bookmarks,include_r18,

POST   /watches                      ← {slug,label,pixiv_tags,match_terms,...}
PATCH  /watches/{slug}
DELETE /watches/{slug}?purge=false   purge=true also deletes its blobs
POST   /watches/validate             ← {pixiv_tag} → {tag,total,sample:[{illust_id,thumb_url}]}
                                        (design; superseded by /pixiv/probe below)
POST   /watches/{slug}/tags          ← {tag, action: "watch"|"ignore"} → watch   (§4b.3)
```

### Character form (built; replaces `/watches/validate`)

```
POST   /pixiv/probe                  ← {tags:[≤8], include_r18}

                                        suggestions:[{tag_raw,tag_norm,posts,share,characters,score}],

```

### Jobs & events

```
POST   /jobs                         ← {type, params:{watches?:[slug], limit?}}
                                     → 202 {job_id}
GET    /jobs?state=&limit=50         → [job]
GET    /jobs/{id}                    → job + last 200 log lines
POST   /jobs/{id}/cancel             → 202
GET    /events                       → text/event-stream
```

SSE event types (each `data:` is JSON):

```
job.queued     {job_id, type, params}
job.started    {job_id, type, started_at}
job.stage      {job_id, stage, feed}            stage: discover|detail|link|download
job.progress   {job_id, done, total|null, rate_per_min}
job.item       {job_id, source, external_id, action}   action: new|seen|dupe|failed
job.log        {job_id, level, message, ts}
job.finished   {job_id, state, counters:{new,seen,downloaded,dupes,failed}}

library.media  {sha256, slug, source, external_id}      → live gallery insert
```

`Last-Event-ID` is honoured; the daemon keeps the last 500 events in a ring
buffer so a reconnect during a long crawl does not lose the pipeline view.

### Gallery

```
GET /gallery                         → [{slug,label,cover_sha,image_count,
                                         post_count,latest_posted_at}]
GET /gallery/{slug}?cursor=&limit=100&source=&sort=posted|added&r18=exclude
                                     → {items:[{sha256,source,external_id,idx,
                                                width,height,posted_at,
                                                artist_name,thumb_url}],
                                        next_cursor}
GET /posts/{source}/{external_id}    → full detail for the aside, including
                                        {linked:[{source,external_id,permalink,
                                                  posted_at,distance}]}
GET /media/{sha256}/thumb?w=400      → image/webp, Cache-Control: immutable
GET /media/{sha256}/full             → original bytes, supports Range
GET /gallery/{slug}/tags?state=&limit=40   → ranked observed tags               (§4b.2)
```

`?token=` is accepted on `/events`, `/media/*` and `/preview/*` only (neither
`EventSource` nor `<img>` can set headers); everywhere else the bearer header
is required.

`sha256` is an immutable content address, so `Cache-Control: public,
max-age=31536000, immutable` is correct and the webview will never re-request a
thumbnail it has seen. This matters more than it sounds for scroll performance.

```

```

## 7. What changes in the engine

The existing package is close to unmodified. Additions, in dependency order:

1. `coreflame/jobs.py` — job table, queue, worker thread, cancellation flag.
2. **Progress callbacks.** `poll_pixiv` / `poll_twitter` / `download_pending`
   currently return a `RunStats` at the end. They gain an optional
   `on_event: Callable[[dict], None]` invoked per record. This is the only
   invasive change, and it is additive — the CLI passes `None` and behaves
   exactly as today.
3. `coreflame/seen.py` — the visited set (§4b.1): the `seen_posts` gate called
   from `_search_tag` before any detail request, the four states, and the
   threshold-invalidation query. This is the highest-leverage change in the
   list — it removes work rather than adding it.
4. `coreflame/tags.py` — `post_tags` write on ingest, `tag_stats` rebuild, and the
   rarity-weighted ranking (§4b.2).
5. `coreflame/thumbs.py` — WebP generation on ingest, called from
   `download_pending` right after `blobs.put()`.
6. `coreflame/library.py` — `by-character/` symlink view, reindex, verify.
7. `dawnmaker/` — FastAPI app, SSE hub, static file serving of the built Vue
   SPA. **The daemon imports the engine; the engine never imports the daemon.**

The CLI keeps working throughout, which is what makes this safe to build
incrementally — and keeps a working escape hatch when the UI is mid-refactor.

## 8. Failure modes

| Symptom | Cause | Guard |
|---|---|---|
| Gallery scroll janks, memory climbs | Full-size images in the grid | Thumbnails at ingest; grid never links `/full` |
| Rows duplicate/skip while scrolling | Offset pagination + concurrent inserts | Keyset cursor on `(posted_at, external_id)` |
| Crawl keeps running after window close | Only Rust-side kill; shell was force-quit | Three layers: managed `CommandChild` kill, daemon heartbeat timeout, lockfile (§2.1) |
| Running crawl dies on every lid-close | Heartbeat timeout counted across sleep | Monotonic gap > 5 min → treat as wake, grant grace period (§2.1) |
| Gallery images silently blank, no error | Tauri CSP blocks loopback `img-src` | Port-wildcard loopback in `csp` (§2.3) |
| Two daemons fighting over the db | Second launch while first is alive | Lockfile with PID; attach instead of spawn (§2.1) |
| 3-second cold start, Defender quarantine | PyInstaller `--onefile` extraction | `--onedir` under `bundle.resources` (§2.4) |
| Sidecar not updated after an app update | `externalBin` + NSIS known issue | Ship it as a resource (§2.4) |
| App launches, sidecar is killed on macOS | Inner Mach-Os unsigned | Sign leaves before the bundle (§2.5) |
| DB corrupt after moving the folder | SQLite on a synced/network path | db stays in app-data; only blobs move |
| Progress bar lies | Guessed denominator | `total: null` → indeterminate |
| Pipeline page blank after sleep | SSE dropped, no replay | `Last-Event-ID` + 500-event ring buffer |
| A local process reads the archive | Open localhost port | Ephemeral port + bearer token + Host/Origin check |
| Broken thumbnails after manual folder edits | Blobs deleted outside the app | `POST /library/verify` marks missing rows `failed` |
| Archive silently doubles in size | Library in a sync folder; client materialises each hardlink | Warn at folder-pick if under a known sync root (§3.1) |
| Deleting images frees no space | Blob still holds the other link | `POST /library/gc` (§3.1) |
| `by-character/` empty on an external drive | exFAT has no hardlinks | Detect `link_mode` at library-init, fall back to copy (§3.1) |
| Imported folder loses its originals | `--move` on a first run | Copy is the default; `--move` opt-in (§3.2) |
| macOS forgets folder access | No security-scoped bookmark | Re-prompt on `PermissionError`, store the bookmark |

## 8b. Shipping updates — git push to installed app

Curio is installed software, so a fix that lands on `main` reaches the user only
if the app goes and gets it. Tag → CI builds every platform → GitHub Release
carries a signed manifest → the running app notices and offers to restart.

```
git tag v0.4.0 && git push --tags
        │
        ▼  GitHub Actions matrix (macos arm64 · macos x64 · windows · linux)
   build-sidecar.sh (PyInstaller --onedir)  →  tauri-action
        │                                        signs each bundle
        ▼
   GitHub Release v0.4.0  +  latest.json  ← the update endpoint
        │
        ▼  app checks on launch if a day has passed, then daily
   download → verify signature → stage → "Restart to update"
```

### 8b.1 Signing is not optional and the key is the whole security model

`tauri-plugin-updater` refuses any bundle whose minisign signature does not
match the public key compiled into the app. Generate once
(`tauri signer generate`), put the **public** key in `tauri.conf.json`, and keep
the private key and its password as CI secrets
(`TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`).

That key is the update channel's root of trust: anyone holding it can ship
arbitrary code to every install. It never goes in the repo, and losing it means
every existing install is permanently stranded — they will only accept updates
signed by the key they shipped with. Back it up somewhere you would back up a
password.

```json
"plugins": {
  "updater": {
    "pubkey": "dW50cnVzdGVkIGNvbW1lbnQ6…",
    "endpoints": [
      "https://github.com/<owner>/curio/releases/latest/download/latest.json"
    ],
    "windows": { "installMode": "passive" }
  }
}
```

`latest.json` is what `tauri-action` emits when updater artifacts are enabled —
`version`, optional `notes`/`pub_date`, and a `platforms` map keyed
`darwin-aarch64` / `windows-x86_64` / `linux-x86_64`, each carrying the bundle
`url` and the **contents** of its `.sig` file (not a path to it).

### 8b.2 The sidecar rides along — because it is a resource

The Python daemon ships inside the bundle under `bundle.resources` (§2.4), so an
update replaces the app **and** `dawnmaker` as one atomic artifact. There is no
second update channel to keep in sync, and no version skew between shell and
daemon — which is the failure this design was always most exposed to.

This is also the second reason to have avoided `externalBin`: the NSIS installer
has a known issue where it does not replace `externalBin` binaries on update,
which would leave a new shell driving an old daemon on Windows only. Resources
are replaced normally.

### 8b.3 Never update over a running crawl

This is the app-specific rule, and skipping it corrupts things.

Installing means killing `dawnmaker` and relaunching. If a crawl is mid-flight,
that kills it between a blob write and its `media` row, or between a batch of
records and its watermark advance. The design already tolerates a crash there —
the watermark only advances after a feed is fully walked, and every write is an
idempotent upsert — but "tolerable" is not a reason to do it on purpose.

So the update gate is:

1. Check and **download** whenever; downloading is free and touches nothing.
2. **Install only when the job queue is idle.** With a job running, the UI shows
   "Update ready — will install when the current crawl finishes", and the
   updater waits.
3. On install: cancel cooperatively (the worker's flag, checked between records),
   wait for the daemon to release the SQLite lock, then relaunch.
4. Never auto-install silently. A personal archive tool restarting itself
   mid-crawl is a bug, not a convenience.

### 8b.4 The database outlives the bundle, so it needs migrations

`~/.reaver/reaver.db` is deliberately outside the library folder *and* outside
the bundle, so it survives every update untouched — which means a v0.4 daemon
opens a v0.3 schema on first launch after an update.

- `schema_version` table; **forward-only** migrations applied by the daemon at
  startup, inside one transaction each.
- **Back up the db file before any migration** (`reaver.db.pre-v0.4.bak`). It is
  small, migrations are rare, and it is the only undo that exists.
- Record `min_app_version` in the db when a migration lands. An older shell that
  finds a newer schema must refuse to start with a clear message rather than
  half-reading it — the one scenario the updater cannot cause but a manual
  downgrade can.
- Content-addressed blobs and thumbnails are format-stable; nothing about an
  update touches the library folder.

### 8b.5 CI shape

```yaml
on:
  push:
    tags: ['v*']
jobs:
  release:
    strategy:
      matrix:
        include:
          - { os: macos-latest,   args: '--target aarch64-apple-darwin' }
          - { os: macos-latest,   args: '--target x86_64-apple-darwin'  }
          - { os: ubuntu-22.04,   args: '' }
          - { os: windows-latest, args: '' }
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5      # sidecar first --
      - run: pip install -e './reaver[daemon]' pyinstaller
      - run: ./deliverer/scripts/build-sidecar.sh   #   or tauri-action
                                                    #   bundles a stale one
      - uses: actions/setup-node@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: tauri-apps/tauri-action@v0
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}
          TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_KEY_PASSWORD }}
          APPLE_CERTIFICATE: ${{ secrets.APPLE_CERTIFICATE }}
          APPLE_ID: ${{ secrets.APPLE_ID }}
          APPLE_PASSWORD: ${{ secrets.APPLE_PASSWORD }}
        with:
          tagName: v__VERSION__
          releaseName: 'Curio v__VERSION__'
          args: ${{ matrix.args }}
```

**The sidecar build must run before `tauri-action`**, or the bundle ships
whatever `resources/sidecar/` happened to contain — which on a clean runner is
nothing, and locally is last week's daemon. The macOS leaf-signing loop in
`build-sidecar.sh` (§2.5) runs here too, before Tauri signs the app around it.

Version lives in `tauri.conf.json`; `__VERSION__` is substituted by the action,
so the tag, the release name and the manifest cannot drift apart.

### 8b.6 Failure modes

| Symptom | Root cause | Guard |
|---|---|---|
| Update installs, app runs old scraper | Sidecar built after `tauri-action`, or not at all | Build the sidecar as an earlier CI step (§8b.5) |
| Windows updates ship a stale daemon | `externalBin` not replaced by NSIS | Ship the sidecar under `bundle.resources` (§2.4) |
| Crawl dies mid-write on update | Installed while a job was running | Install only when the queue is idle (§8b.3) |
| App won't start after an update | Schema migrated, migration failed halfway | Forward-only migrations in one transaction + pre-migration backup (§8b.4) |
| Downgrade half-reads a newer db | No floor recorded | `min_app_version` in the db; refuse and say so |
| No client ever updates again | Signing key lost | The key is the root of trust — back it up off-repo |
| `latest.json` 404s | Release published as draft | `releaseDraft: false`, or publish the draft |

## 9. Build order

Each step ends somewhere usable, which is what keeps a side project alive:

1. `seen.py` — the visited gate. Ship it first: it is a correctness fix
   (deleted artworks stop being re-fetched) and it makes every later run
   cheaper.
2. `net.py` — the DoH backend and the diagnostic (§4c). Early, because on a
   connection where pixiv is blocked nothing else can be tested at all.
3. `jobs.py` + progress callbacks, driven from the CLI. No UI.
4. `dawnmaker` with `/health`, `/stats`, `/jobs`, `/events`. Verify with `curl`.
5. Thumbnails + `/media/{sha}/thumb`. Verify in a browser tab.
6. Vue SPA: **pipeline page first** — it is the one that proves SSE, jobs and
   cancellation all work end to end.
7. Crawl config page. At this point the CLI stops being necessary.
8. Gallery + character detail + aside, plus the observed-tags strip.
9. `by-character/` hardlinks, `verify`/`gc`, `import`, folder picker.
10. Tauri shell: window + `daemon_endpoint` command + the three lifecycle
   layers. Run against `python -m dawnmaker` in dev the whole time.
11. Package: PyInstaller `--onedir` → `bundle.resources` → sign → notarize.
   Budget a full day for this step on macOS alone; it is the one that always
   takes longer than it should.
12. Updater last (§8b): generate the signing key, wire the CI matrix, and only
   then turn on the update check in the app. Shipping an updater before the
   build pipeline is reliable means shipping a broken app that can update
   itself into a worse one.

## 10. Implemented since the design

What the repo has that this document did not anticipate, or decided
differently. Each item names the file that owns it.

### 10.1 Sign-in without a password (`deliverer/src-tauri/src/auth.rs`, `dawnmaker/auth.py`)

The design had `POST /sources/pixiv/session` taking a pasted `PHPSESSID`. As
built, the shell's `source_login` command opens the site's **own** login page
in a second window (label `source-login`, absent from the capabilities file
so remote content has no IPC), polls `cookies_for_url` every 500 ms for up to
300 s until the needed cookies exist (`PHPSESSID`; `auth_token` + `ct0`),
closes the window and returns them to the webview, which posts them to
`/api/auth/<source>`. The cookie is never kept in the webview or localStorage.
The daemon **verifies before it stores**: a pixiv cookie must pass one search
request — the request the crawl needs — or the previous cookie stays and the
call is 401 `session_rejected`. Cookies live in `~/.reaver/secrets.json`
(0600, written only by `Config.save_secrets()`); `config.json` never contains
them and `/api/config` redacts them to booleans. `PIXIV_PHPSESSID` in the
environment still overrides. X cookies become `~/.reaver/twitter-cookies.txt`
(0600) for gallery-dl and are reported as "stored", since no cheap
verification exists. At daemon start a stored pixiv cookie is re-verified on a
background thread; the rail badge shows "checking…" then "connected" or
**Session expired**. `poll_pixiv` refuses to start unauthenticated rather
than 401-ing per tag. UI: `AuthGate` on first launch while nothing is
connected ("Browse offline" dismisses it per install via localStorage);
Settings › Accounts (`SourceCard`) is the permanent home. Outside Tauri
(browser-mode Docker) `SourceCard` unfolds a developer paste form instead.
Flow: `docs/flows.md` §e.

### 10.2 Character form probe, preview and suggestions (`dawnmaker/probe.py`, `WatchForm.vue`)

`POST /api/pixiv/probe` replaces `/watches/validate`: one listing page per
tag (max 8 per call), cached per (tag, R-18 mode) for 10 min, never a detail
fetch, nothing written to `seen_posts` or blobs. It returns per-tag totals, a
12-image preview merged newest-first across tags, up to 12 suggested tags from
`tags.suggest_from_listing` and a backfill estimate. Fullwidth `（）` is flagged
locally without a request. `GET /api/preview/{id}/thumb` proxies `i.pximg.net`
(Referer required, CSP allows only 127.0.0.1) for probed ids only, cached
15 min, at most 256 in memory — not a general image proxy. The form debounces
350 ms. Flow: `docs/flows.md` §f.

### 10.3 Auth routes

`POST/DELETE /api/auth/pixiv`, `POST /api/auth/pixiv/verify`,
`POST/DELETE /api/auth/twitter`; `GET /api/sources/status` grew `verified`,
`error` and a `network` block. Appended to §6.

### 10.4 `--host` and `--dev` (`dawnmaker/__main__.py`)

`--dev` disables nothing security-wise except that it adds
`http://localhost:*` and `http://127.0.0.1:*` to the allowed request origins
(Vite). `--host` other than loopback is refused unless `--dev` is also given;
it exists only so the Docker container can bind `0.0.0.0` while compose
publishes the port on `127.0.0.1`. `--no-heartbeat` keeps a hand-started
daemon alive.

### 10.5 One `Store` per request (`dawnmaker/app.py`)

A thread-local connection cache is wrong here: FastAPI runs the `Depends`
provider and a sync endpoint on different threadpool threads, and the SSE
stream pins one of those threads for its whole lifetime. As built,
`State.open_store()` opens a `Store(check_same_thread=False)` for exactly one
request and the dependency closes it afterwards.

### 10.6 CORS (`dawnmaker/security.py`)

The webview (`tauri://localhost` on macOS, `http://tauri.localhost` on
Windows) is always a different origin from the daemon, so every request is
CORS and the browser preflights anything carrying `Authorization`. The
middleware answers `OPTIONS` itself with 204 and reflects only an allowed
origin (never `*`), before the token check — a preflight carries no
`Authorization` by definition. `?token=` is accepted on `/api/events`,
`/api/media/*` and `/api/preview/*` only. Flow: `docs/flows.md` §i.

### 10.7 Updater as built (`deliverer/src/stores/updater.ts`, `UpdateBanner.vue`, `UpdatesPanel.vue`)

Phases `idle → checking → available → downloading → ready → (waiting) →
installing → relaunch`, plus `error` and `unsupported` (browser mode). Checks
at boot if the last check is older than a day, then every 24 h, and on "Check
now". `install()` refreshes `/api/health` and waits in `waiting` (5 s poll)
while `idle` is false — the §8b.3 gate. "Install automatically" chains
download and install behind the same gate. Settings › Updates renders
`CHANGELOG.md` (imported as text at build time) and shows a `daemonMismatch`
warning when the shell's `__APP_VERSION__` differs from `/api/health`'s
`version` — the §8b failure surfaced to the user. `lastChecked`/`auto` persist
in localStorage. Flow: `docs/flows.md` §g.

### 10.8 Versioning scripts (`scripts/`)

`bump-version.sh X.Y.Z` writes `tauri.conf.json` (source of truth),
`deliverer/package.json`, `reaver/pyproject.toml`, `coreflame/__init__.py`,
promotes `## Unreleased` in `CHANGELOG.md` and refreshes the lockfile;
`check-version.sh` is the CI gate (all four agree, and match the tag);
`install-linux.sh` is the one-line Linux installer attached to each release.

### 10.9 CI matrix (`.github/workflows/release.yml`)

Differs from §8b.5 in three ways: a separate `check` job (version gate,
`reaver/check.sh`, deliverer `check`) runs first; the Intel build uses
`macos-13` (the last Intel runner) and Linux `ubuntu-22.04` (oldest glibc we
ship); each build job builds the sidecar, **smokes it** (`dawnmaker --help`),
then runs `tauri-action` with `--target` and `--bundles` (`dmg` / `nsis` /
`appimage,deb`), `releaseDraft: true` and `includeUpdaterJson: true`. A
`linux-installer` job attaches `scripts/install-linux.sh`. `pnpm` throughout
(`pnpm/action-setup`, `tauriScript: pnpm tauri`). Flow: `docs/flows.md` §h.

### 10.10 Docker stack (`docker/`, `docker-compose.yml`)

Browser mode only — the Tauri window cannot run in a container. One image
(`python:3.12-slim` + Node 22 + pnpm via corepack) runs `dawnmaker --host
0.0.0.0 --port 8765 --no-heartbeat --dev` and Vite; the entrypoint waits for
`DAWNMAKER_READY` and hands port and token to Vite through the environment.
Ports are published on `127.0.0.1` only; the archive is a bind mount
(`./data` or `CURIO_DATA`); `node_modules` are container-only volumes;
secrets come from a root `.env`. `docker compose run --rm dev coreflame …`
for the CLI. Details: `docs/build.md`.

### 10.11 Design system as built (`deliverer/src/styles.css`, `stores/theme.ts`)

Tailwind v4, CSS-first: the `@theme` block is the config. Tokens: the sampled
"cyber build" palette (hue-265 neutrals, magenta `ember` accent, `cyan` for
the cross-source link, `moss` ok, `rose` error; no default palette), a fixed
px spacing ladder (`0 3 5 10 15 … 500`), a six-step type ramp
(`xsmall small base medium extra ultra`), fonts Chakra Petch / IBM Plex Mono /
Noto Sans JP, radii reset to square with one `rounded-chip`. Signature
utilities `cut`, `scan`, `data`, `container`, `h-custom-screen`; component
classes `.btn .panel .chip .phead .ptitle .field .bar .rk-*`; Reka UI for
behaviour only. Corner modes: square by default, `corners-cut` on `<html>`
from Settings › Theme, `.panel.poly` / `.panel.square` per panel. The theme
store re-hues the neutral ladder from one picked background with
`color-mix(in oklch)`, flips text on a light canvas, and persists to
localStorage only. Flow: `docs/flows.md` §j.

### 10.12 i18n (`deliverer/src/i18n.ts`, `src/locales/`)

vue-i18n 11, composition API; one JSON per page or component
(`app auth character crawl gallery pipeline settings updates`), loaded by
glob, file name = key prefix. English is complete and the fallback; `ja id zh
fil` are listed and enabled per locale with `ready: true`. No literal
user-visible text in templates; `scripts/i18n-check.mjs` (part of `check`)
fails on an unresolved key or leftover prose. Data (tags, artist names, job
types, daemon error strings) is never translated.

### 10.14 Smaller deltas

- `Heartbeat` has a 300 s sleep grace on top of the 30 s timeout (§2.1): a
  gap that long is a laptop wake, so the daemon grants one more timeout.
- The lockfile is only considered live if the recorded pid exists **and**
  something answers on the recorded port — pid reuse in containers and
  after a macOS reboot fooled the pid-only check.
- `PUT /api/config` refuses a `library_root` under a sync folder
  (`library.under_sync_root`) with 400 `sync_folder`.
- The rail has a **Shutdown app** command (`lib.rs::shutdown_app`): daemon
  first, then the process; with a job running it asks for a second click.
- `docker-compose.yml`'s header comment still says `npm run tauri dev`; the
  command is `pnpm tauri dev` (`deliverer/CLAUDE.md`).
